# Методические указания преподавателям по использованию ресурсов

Указания описывают, как подбирать и обновлять [информационные ресурсы](../../resources/README.md), готовить индивидуальные варианты заданий и поддерживать работоспособность учебного окружения. Задача — чтобы каждый КИМ был обеспечен доступным ресурсом, а задания оставались устойчивыми к решению «в одно обращение к ассистенту».

## 1. Принципы подбора ресурсов

1. **Ресурс добавляется под КИМ.** Каждая карточка ресурса содержит ссылку на КИМ, который он обеспечивает. Ресурс, не связанный ни с одним КИМ, в раздел не включается.
2. **Гарантированный доступ.** Приоритет — источникам, бесплатным для обучающихся: ЭБС вуза, открытые авторские версии учебников, arXiv, open source. Платный или ограниченный ресурс сопровождается бесплатной альтернативой.
3. **Минимальное окружение.** Прежде чем добавлять библиотеку, проверьте, не покрывается ли задача уже включённой. Разрастание окружения ухудшает воспроизводимость и увеличивает долю времени, уходящего на установку.
4. **Правовая чистота.** Защищённые авторским правом файлы в репозиторий не размещаются — только библиографическое описание и способ легального доступа. Данные индустриальных партнёров используются обезличенно и в объёме, разрешённом соглашением.

## 2. Подготовка к семестру: чек-лист

Выполняется ответственным преподавателем **до начала занятий**:

- [ ] проверена доступность всех внешних ссылок в `resources/`; неработающие заменены, даты проверки обновлены;
- [ ] зафиксированы версии библиотек в `requirements.txt` курса; собран и проверен контейнер окружения;
- [ ] проверены минимальные примеры по каждой библиотеке (после мажорных обновлений API часто меняется);
- [ ] подтверждён доступ к LLM-сервису (квоты, ключи) либо развёрнута локальная альтернатива;
- [ ] получены кейсы индустриальных партнёров на текущий год либо подготовлены модельные кейсы той же структуры;
- [ ] обновлены банки заданий (см. регламент ниже), сформированы комплекты вариантов по числу обучающихся;
- [ ] проверена доступность вычислительных ресурсов для ЛР 5.1 и экзаменационного задания;
- [ ] в СДО загружены банки тестов с ключами, настроены выборка и прокторинг.

## 3. Обновление банков заданий

| Банк | Норма обновления | На что смотреть |
|---|---|---|
| [Банки тестов](../../resources/test-banks/README.md) | не менее 20 % заданий ежегодно | задания с долей верных ответов выше 95 % или ниже 20 % — пересматриваются |
| [Банки задач и кейсов](../../resources/problem-banks/README.md) | не менее 30 % вариантов ежегодно | варианты, по которым появились готовые публичные решения; варианты с непропорциональной трудоёмкостью |
| Комплект экзаменационных билетов | ежегодно | сбалансированность: каждый билет содержит вопрос групп A и B, вопросы не из одного модуля |

Изменения фиксируются с указанием даты, автора и причины: журнал версий банка в СДО, для открытой части — история коммитов репозитория.

## 4. Как готовить варианты, устойчивые к ИИ-ассистентам

Полностью исключить ассистентов невозможно, поэтому задания строятся так, чтобы готовый текст не заменял работу:

1. **Требуйте собственных измерений.** Задание должно опираться на данные, которые обучающийся получил сам: журнал запусков, разброс по seed, поведение при отказе. Ассистент не может подставить чужие числа так, чтобы они согласовались с журналом и защитой.
2. **Индивидуализируйте параметры.** Различайте среду, число агентов, топологию, профиль нагрузки, вид нарушенного режима — не менее 8 вариантов на работу.
3. **Спрашивайте про отклонённые альтернативы.** Обоснование выбора и границы применимости требуют связи с конкретными ограничениями варианта, а не общих формулировок.
4. **Включайте изменение «на месте».** Любое задание должно допускать быструю модификацию на защите с предсказуемым эффектом.
5. **Проверяйте задание ассистентом сами.** Если модель выдаёт решение, удовлетворяющее рубрике, без экспериментальных данных — переформулируйте задание либо усильте требования к доказательствам.

Шаблон промпта для генерации вариантов и правила проверки сгенерированного — в [resources/llm-prompts](../../resources/llm-prompts/README.md#учебные-шаблоны-промптов). Сгенерированные варианты и тестовые задания перед использованием проверяет преподаватель: LLM применяется как инструмент подготовки, но не как источник эталонных ответов.

## 5. Ресурсы по модулям

| Модуль | Что должно работать к началу модуля |
|---|---|
| [М1](../../M1-agent-architectures/README.md) | Python-окружение, SPADE или Mesa, NetworkX; примеры моделей NetLogo для демонстрации эмерджентности |
| [М2](../../M2-coordination/README.md) | среда для Contract Net / аукционов; генератор потока заявок с фиксируемым seed |
| [М3](../../M3-game-theory/README.md) | Nashpy и Axelrod; банк расчётных задач по равновесиям |
| [М4](../../M4-swarm-intelligence/README.md) | PySwarms, NetworkX; экземпляры TSPLIB с известными оптимумами как эталон качества |
| [М5](../../M5-marl/README.md) | PettingZoo, Gymnasium, Ray RLlib; проверенные вычислительные квоты; заранее посчитанные ориентиры по времени обучения |
| [М6](../../M6-llm-mas/README.md) | доступ к LLM-сервису, MCP-инструменты, трассировка (OpenTelemetry); бюджет вызовов на группу |

Перечни и лицензии — в [resources/software/python-libs](../../resources/software/python-libs/README.md); среды и данные — в [datasets](../../resources/datasets/README.md) и [benchmarks](../../resources/benchmarks/README.md).

## 6. Типичные затруднения и как их снимать

| Затруднение | Решение |
|---|---|
| Обучение MARL не укладывается в отведённое время | Уменьшить масштаб среды и число шагов; засчитывать корректную методику сравнения, а не абсолютное качество обучения |
| Нет доступа к облачному LLM-сервису | Локальная модель через совместимый API; при её отсутствии — вариант с углублённым контуром MARL ([КИМ-Э.2](../../Exam/kim-02-practical-task.md)) |
| Партнёр не предоставил кейс к сроку | Модельный кейс преподавателя той же структуры: процесс, ограничения, критерии качества |
| Разная подготовка обучающихся по RL | Направить к материалам для восполнения пререквизитов — [Sutton & Barto](../../resources/textbooks/README.md), [HF Deep RL Course](../../resources/other/README.md) — до начала модуля 5 |
| Библиотека сломалась после обновления | Зафиксировать рабочую версию в `requirements.txt`, отметить в карточке ресурса дату и версию, при необходимости перейти на альтернативу |

## 7. Ответственность за раздел ресурсов

- Ответственный преподаватель поддерживает актуальность `resources/`, подтверждает доступность ссылок перед семестром и обновляет даты проверки.
- Предложения по новым ресурсам вносятся через issue или pull request с заполненной [карточкой ресурса](../../resources/README.md#единая-карточка-ресурса) — см. [CONTRIBUTING](../../CONTRIBUTING.md).
- Ресурсы, потерявшие связь с КИМ после переработки заданий, удаляются из раздела вместе с соответствующими ссылками.
