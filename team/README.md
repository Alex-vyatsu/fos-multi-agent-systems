Ниже перечислены виды работ по принципу CRediT. Каждый вид выполнен командой совместно — обсуждение решений, разработка материалов и взаимная проверка велись коллективно.

| Вид вклада | Содержание |

| Разработка рубрик | 17 рубрик оценивания: критерии, веса, блокирующие условия, правила перевода в итоговую оценку |
| Ресурсное обеспечение | Подбор [литературы, публикаций, программных средств и сред](../resources/README.md); спецификации банков заданий; правила использования LLM |
| Методические указания | [Рекомендации обучающимся и преподавателям](../methodical-guidelines/README.md) по выполнению, оцениванию и ресурсному сопровождению |
| Валидация и проверка | Сверка ФОС с [РПД](../docs/rpd.md) и КРМ, проверка покрытия индикаторов и согласованности баллов, [автоматические проверки](../other/tools/check_links.py) ссылок и весов рубрик, [чек-лист готовности](../docs/quality-checklist.md) |

## Порядок работы команды

1. Участники вносят материалы **через собственные GitHub-аккаунты**, чтобы история коммитов отражала ход совместной работы (см. [README §8](../README.md#8-команда)).
2. Изменения оформляются по [правилам внесения изменений](../CONTRIBUTING.md): отдельная ветка, одно логически завершённое изменение за коммит, указание затронутых индикаторов и КИМ в описании Pull Request.
3. Изменения, затрагивающие систему баллов, пороги или состав КИМ, согласуются командой и фиксируются в [чек-листе готовности](../docs/quality-checklist.md).
4. Материалы, подготовленные с участием индустриальных партнёров (кейсы, данные), сопровождаются указанием организации-партнёра и условий использования.
