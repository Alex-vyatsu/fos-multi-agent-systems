# DPF-аудит итерации 1.2.0

## Граница и допустимый вывод

**Объект:** открытый репозиторий ФОС и минимальный CPU-only исполняемый
контур.  
**Вне границы:** СДО с закрытыми банками, инфраструктура вуза, реальные
LLM/API, полная реализация A2A/MCP и организационное утверждение.  
**Доверительные домены:** репозиторий команды; личный учебный репозиторий;
контур преподавателя/СДО; внешние источники; внешний агент; MCP tool/resource.  
**Внешний эффект baseline:** отсутствует; примеры только формируют артефакт и
trace в памяти/стандартном выводе.  
**Допустимый риск:** локальный обратимый эксперимент без секретов, платежей,
персональных данных и автономных значимых действий.  
**Проверяемый результат:** clean run, атомарная трасса КРМ, contract/negative
tests и явные blockers.

## Матрица приемки

Используются статусы профиля `pass`, `fail`, `blocked`, `not_applicable`.
Профиль получает `pass` только при прохождении всех его обязательных строк.

| Профиль | Статус | Evidence | Что не доказано / ремонт |
|---|---|---|---|
| `FOS-CP-01` минимальный исполняемый комплект | **pass** | [`requirements.txt`](../requirements.txt), [host build/run record](clean-run-2026-07-27.md), [М1–М6 и exam baselines](../examples/README.md), генератор/данные, 14 тестов | Dockerfile является отдельным неквалифицированным recipe; Docker image не входит в основание этого `pass` |
| `FOS-CP-02` атомарная модель измерения | **pass** | [`indicator-evidence.csv`](../data/indicator-evidence.csv), [читаемая матрица](indicator-evidence.md), `check_traceability.py` | педагогическая валидность критерия остаётся предметом внешней экспертизы |

компенсируется высоким баллом технических критериев.

## Типы утверждений

- **Наблюдаемый факт:** clean run minimal прошёл; точные команды и результаты
  записаны в протоколе.
- **Локальное обязательное требование:** КИМ/рубрики требуют разделять A2A и
  MCP и предъявлять negative tests.
- **Стабильный нормативный baseline рамки:** A2A `1.0.0`, MCP `2025-11-25`;
  source IDs `SRC-A2A-100`, `SRC-MCP-20251125`.
- **Рекомендация:** параметры recommended/extended профиля требуют
  институциональной квалификации.
- **Вывод:** повышение внутренней оценки до 187/210 обосновано новыми
  evidence, но не подтверждает официальный выпуск или сертификацию.

## Негативный путь и восстановление

| Сценарий | Ожидаемая граница | Evidence |
|---|---|---|
| missing dataset | явная ошибка с командой генерации | `test_exam_smoke_reports_missing_dataset` |
| неизвестная capability/версия/agent | отказ до делегирования | contract tests |
| grant истёк | нет tool artifact, задача переходит в `failed` | contract tests |
| scope запрещён | вызов отклонён до эффекта, artifact отсутствует | contract tests |
| tool недоступен | `failed`, затем отдельный безопасный recovery | exam E2E |
| повтор effect key | один artifact, двойного эффекта нет; grant проверяется повторно | idempotency/auth test |
| cancel | переход в `canceled` до эффекта | lifecycle test |
| опасный запрос | `blocked`, `executed = false` | guarded orchestrator test |

## Следующий первый шаг

Организация назначает `FOS_MAINTAINER` и `REPRODUCIBILITY_OWNER`. После этого
владелец выпускает семестровый lock-файл рекомендуемого профиля, выполняет
clean run M2/M5/M6 с реальными библиотеками и публикует датированный external
link report. Закрытие проверяется повторным запуском `check_all.py` и новой
qualification record; отсутствие назначения остаётся blocker, а не
автоматически «выполненной» задачей.
