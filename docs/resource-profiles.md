# Профили ресурсов и границы воспроизводимости

Профиль определяет не «качество студента», а условия, в которых проверено
исполнение задания. Одинаковыми для всех профилей остаются инженерное решение,
наблюдаемые доказательства, негативный сценарий и живая защита. Размер модели,
число GPU и платный API сами по себе баллов не дают.

## Минимальный профиль — квалифицирован

| Параметр | Значение |
|---|---|
| Назначение | стартовые примеры модулей 1–6, генератор данных, contract slice A2A/MCP и экзаменационный smoke-сценарий |
| Hardware | CPU Apple M1 Pro, 16 ГБ RAM; GPU не используется |
| OS и runtime | clean run: Darwin 25.3.0 arm64, CPython 3.12.7; контейнерная цель `python:3.12.13-slim-bookworm` структурно задана, но build не квалифицирован |
| Зависимости | сторонних Python-пакетов нет; [`requirements.txt`](../requirements.txt) намеренно пуст |
| API / сеть / стоимость | не требуются; стоимость внешних вызовов — 0 |
| Данные и повторы | локальный синтетический набор и детерминированный генератор, seed 42; квалификационные прогоны M2/M5 на seeds 7, 42 и 99 |
| Команда | `python other/tools/check_all.py` |
| Проверенный предел | одно чистое окружение, два полных запуска проверок и по три seed для M2/M5; время, допуски и результаты фиксируются в [протоколе clean run](clean-run-2026-07-27.md) |
| Privacy | данные синтетические; секреты и персональные данные не нужны |
| Что подтверждается | запуск малоресурсных baseline, детерминизм, базовые метрики, отказные пути, семантика границ A2A/MCP |
| Что **не** подтверждается | wire-conformance A2A/MCP, качество реальной LLM, полные PettingZoo/RLlib/CTDE-сценарии, производительность на других ОС |

## Рекомендуемый профиль — специфицирован, не квалифицирован

| Параметр | Значение |
|---|---|
| Назначение | полное выполнение лабораторных работ с типовыми открытыми библиотеками и локальным LLM fallback |
| Hardware | не менее 4 CPU-ядер, 16 ГБ RAM, 10 ГБ свободного диска; GPU от 8 ГБ VRAM — только для локальной модели |
| Software | CPython 3.12; PettingZoo/Gymnasium, Nashpy/Axelrod, PySwarms, выбранный MARL- и LLM-стек |
| Фиксация версий | преподаватель выпускает семестровый lock-файл после pilot run; до его появления профиль имеет статус `не квалифицирован` |
| API / сеть / стоимость | платный API не обязателен; при облачном варианте квота и предельная стоимость назначаются до выдачи задания |
| Время | целевой smoke ≤ 30 мин; MARL-прогон ≤ 60 мин на конфигурацию; превышение требует уменьшения среды или отдельного расширенного профиля |
| Privacy | локальный вариант — по умолчанию; отправка учебных или партнёрских данных во внешний API требует разрешения и обезличивания |
| Достижимые результаты | реальные библиотечные среды, несколько seed, локальная модель или ограниченный облачный вызов |
| Что **не** подтверждается | переносимость на произвольный hardware, промышленная эксплуатация, достаточность одной модели/одного seed |
| Blocker квалификации | семестровый lock-файл, чистый запуск M2/M5/M6 и назначенный `REPRODUCIBILITY_OWNER` |

## Расширенный профиль — проектный

| Параметр | Значение |
|---|---|
| Назначение | исследовательские MARL/LLM-эксперименты, большие среды и сравнение нескольких моделей |
| Hardware | не менее 8 CPU-ядер, 32 ГБ RAM; GPU от 24 ГБ VRAM либо утверждённая облачная квота |
| Software | стек рекомендуемого профиля + средства трассировки, распределённого обучения и experiment tracking |
| API / сеть / стоимость | сеть и внешний API допустимы только после назначения денежного потолка, владельца ключей и режима хранения данных |
| Время | до 4 часов на конфигурацию; не менее 3 seed; длительные задания выносятся из окна живой защиты |
| Privacy | отдельная оценка данных и поставщика; секреты не хранятся в учебном репозитории |
| Достижимые результаты | сравнение моделей и политик, расширенные метрики, исследование масштабирования |
| Что **не** подтверждается | педагогическая эквивалентность минимальному профилю и право на внешнее высокорисковое действие |
| Blocker запуска | утверждённые квоты, бюджет, владелец инфраструктуры и clean run выбранного стека |

## Правило выбора

Минимальный профиль доступен всем и используется для проверки структуры
эксперимента и отказных путей. Рекомендуемый и расширенный профили включаются
только после квалификации конкретного окружения. Детерминированный mock в
модуле 6 подтверждает контракт и обработку ошибок, но не качество или
безопасность реальной LLM.
