# КИМ-2.1. Лабораторная работа «Распределение задач в МАС»

| Параметр | Значение |
|---|---|
| Модуль | 2. Координация, кооперация и коллективное принятие решений |
| Тип КИМ | Лабораторная работа с устной защитой |
| Форма контроля | Текущий контроль |
| Проверяемые индикаторы | O-2.2, O-2.3 (уровень Б) |
| Трудоёмкость | 6 а.ч. (ЛР) + подготовка в СРС 2 |
| Максимальный балл | 5 (см. [rubric-01.md](rubric-01.md)); минимум для зачёта — 3 |

## 1. Назначение и проверяемые результаты обучения

Лабораторная работа проверяет базовый уровень индикаторов **O-2.2** (применение мультиагентных механизмов кооперации и координации) и **O-2.3** (организация взаимодействия агентов при решении частной задачи). По итогам обучающийся:

- **знает** механизмы координации и кооперации агентов, протокол Contract Net, аукционное распределение задач;
- **умеет** реализовать распределение подзадач между агентами и оценить качество распределения;
- **владеет** навыком организации сценария взаимодействия агентов и наблюдения за процессом согласования.

## 2. Условия выполнения

- **Среда и инструменты:** Python 3; собственная реализация обмена сообщениями либо среда моделирования МАС (PettingZoo, Mesa, SPADE или аналог).
- **Форма работы:** индивидуально, по назначенному варианту; командное выполнение — с разделением зон ответственности и индивидуальной защитой.
- **Артефакты ведутся в Git:** код, конфигурация, журнал распределения, инструкция запуска.
- **Регламентированное использование ИИ-ассистентов** — при выполнении условий раздела 6.

### Минимальный воспроизводимый старт

```bash
python resources/datasets/generate_requests.py --seed 42 --count 12 \
  --output resources/datasets/generated/requests_seed42.csv
python examples/m2_contract_net.py --seed 42 --tasks 8
```

Ожидается 12 строк данных и JSON с `task_count = 8`,
`message_count = 40`; идентификаторы задач назначены ровно по одному разу.
Удаление набора данных должно приводить к явной ошибке или документированному
повторному запуску генератора, а не к скрытой подстановке. Пример не выполняет
за студента сравнение с централизованным вариантом. Профиль:
[минимальный](../docs/resource-profiles.md#минимальный-профиль-квалифицирован).

## 3. Задание

1. **Постановка.** Задать задачу, в которой множество задач/заявок распределяется между агентами-исполнителями с разной «стоимостью» выполнения (по варианту).
2. **Протокол.** Реализовать распределение по **протоколу Contract Net** (объявление задачи → предложения агентов → выбор победителя → подтверждение) **или** аукционное распределение (по варианту).
3. **Наблюдаемость.** Журналировать обмен сообщениями: объявления, ставки/предложения, назначения; обеспечить трассируемость решения о назначении.
4. **Оценка качества распределения.** Ввести метрики (суммарная стоимость, загрузка агентов/балансировка, число сообщений/раундов) и измерить их.
5. **Сравнение.** Сопоставить распределённый механизм с централизованным (жадное/оптимальное назначение) по введённым метрикам.
6. **Выводы.** Указать, при каких условиях распределённый механизм предпочтительнее централизованного и какова его цена (накладные расходы на коммуникацию).

## 4. Индивидуализация (примеры вариантов)

| № | Предметный сценарий | Механизм | Что варьируется |
|:--:|---|---|---|
| 1 | Распределение заявок между курьерами | Contract Net | Функция стоимости (расстояние/время) |
| 2 | Назначение задач вычислительным узлам | Аукцион первой цены | Число задач и узлов |
| 3 | Распределение зон патрулирования | Contract Net с переторговкой | Появление новых задач в процессе |
| 4 | Совместная сборка из подкомпонентов | Аукцион второй цены (Викри) | Ограничения совместимости исполнителей |

Иные варианты — по согласованию с преподавателем при сохранении набора артефактов.

## 5. Требования к результату и формат сдачи

Обучающийся предъявляет: исходный код и конфигурацию; журнал распределения (обмен сообщениями и итоговые назначения); таблицу метрик качества распределения и сравнения с централизованным вариантом; краткую инструкцию запуска; выводы. **Формат сдачи:** коммит(ы) в учебный репозиторий + устная защита.

## 6. Живая защита и правила использования ИИ и внешних ресурсов

- Защита **устная**: обучающийся воспроизводит распределение и **на месте изменяет условие** (добавляет задачу/агента или меняет функцию стоимости), объясняя, как перестраивается назначение.
- Вопросы на понимание протокола и роли сообщений в согласовании.
- Репозиторий — артефакт, но не достаточное доказательство самостоятельного понимания.
- ИИ-ассистенты — при обязательном указании промптов и критическом анализе; заимствования помечаются.

## 7. Критерии и шкала оценивания

Оценивание — по [рубрике `rubric-01.md`](rubric-01.md). Работа засчитывается при итоге не ниже **3 из 5** баллов и успешной живой защите (воспроизведение распределения и корректная реакция на изменение условия).
