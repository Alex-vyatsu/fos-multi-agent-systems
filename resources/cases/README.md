## МК-1. Распределение доставок (логистика)

### Исходная ситуация
Оператор последней мили принимает поток заявок на доставку. Исторически диспетчер назначал исполнителей вручную или простым правилом «ближайший свободный». При росте числа курьеров и жёстких SLA ручное назначение не успевает, а централизованный жадный алгоритм даёт локальные конфликты (несовместимые грузы, окна доставки, зоны).

### Бизнес-/технический контекст
- Критерии: доля заявок в срок, среднее время назначения, стоимость рейса, число конфликтов совместимости.
- Риск: автоматика не должна подтверждать доставку опасного/ограниченного груза без ответственной роли.

### Заинтересованные роли
- Заказчик: операционный директор / диспетчерская служба.
- Пользователи: диспетчеры, менеджеры зон.
- Смежные: compliance (ограничения груза), поддержка ИТ.

### Постановка МАС
- Агенты-исполнители предлагают ставки/окна; оркестратор распределяет заявки (Contract Net / аукцион / гибрид).
- Ответственный контур: подтверждение исключений (опасный груз, перегруз зоны) человеком.
- Baseline: централизованный «ближайший свободный».
- Метрики: on-time rate, mean assignment latency, cost, conflict rate; не менее 3 запусков.

### Ожидаемый результат для кейса (СРС)
Матрица альтернатив (workflow / одноагентный / МАС / LLM-оркестратор), обоснование минимально достаточной архитектуры, эскиз ролей и условий пересмотра.

### Данные для работы
Синтетический поток заявок (`RES-DATA-REQ`) или свой набор той же схемы (id, зона, срок, совместимость, приоритет).

## МК-2. Координация мобильных роботов (робототехника)

### Исходная ситуация
На складе или в учебной арене группа мобильных роботов должна собрать объекты и доставить их к пунктам выгрузки. Связь ограничена; столкновения и взаимные блокировки часты при независимом управлении.

### Контекст
- Критерии: число собранных объектов, число столкновений, время эпизода, устойчивость при отказе одного робота.
- Риск: локально оптимальное поведение ухудшает командный результат (нестационарность).

### Постановка МАС / MARL
- Сравнение независимого обучения (IQL) и одной CTDE-схемы на упрощённой среде (или дискретном аналоге).
- Baseline: фиксированные эвристики / независимые жадные политики.
- Обязателен отказной режим: потеря связи или отключение одного агента.

### Ожидаемый результат для кейса
Обоснование, когда классическая координация достаточна, а когда нужен обучаемый контур; эскиз наблюдаемости и метрик безопасности.

### Данные / среды
PettingZoo MPE или упрощённая клеточная карта из примеров курса; журнал экспериментов по шаблону `experiment-log.csv`.

## МК-3. Балансировка ИТ-запросов (распределённые сервисы)

### Исходная ситуация
Сервис обрабатывает поток запросов несколькими воркерами. Нагрузка переменная; узлы отказывают; повторная обработка должна быть идемпотентной.

### Контекст
- Критерии: throughput, p95 latency, error rate, доля успешных retry без двойного эффекта.
- Риск: автоматический ретрай без scope/timeout порождает дубли и каскадные отказы.

### Постановка МАС
- Агенты-обработчики + менеджер нагрузки; явные правила cancel/timeout и безопасного восстановления.
- Baseline: round-robin без учёта состояния.
- Углубление: MARL для политики маршрутизации **или** LLM-помощник для классификации инцидентов с обязательным human approve.

### Ожидаемый результат для кейса
Матрица механизмов координации; указание, где решение принимает человек; протокол нарушенного режима.

### Данные
Генератор заявок с полями приоритета и «стоимости» обработки; сценарий inject-failure по аналогии с `exam_end_to_end.py`.

## МК-4. Микросеть (энергетика)

### Исходная ситуация
Локальная микросеть согласовывает потребление и генерацию домохозяйств/накопителей при ограничениях линии. Центральный диспетчер не масштабируется на частые локальные события.

### Контекст
- Критерии: дефицит/избыток энергии, число нарушений лимита, стоимость балансировки, время согласования.
- Риск: агент не имеет права менять уставку защит без ответственной роли.

### Постановка МАС
- Агенты потребителей/генераторов + координатор; торг или итеративное согласование.
- LLM-контур (по варианту): предложение плана балансировки с обязательной проверкой ограничений правилами/человеком.
- Baseline: централизованный планировщик по среднему прогнозу.

### Ожидаемый результат для кейса
Обоснование МАС vs централизованный SCADA-скрипт; границы применимости при росте числа узлов.

## МК-5. Городские службы (инфраструктура)

### Исходная ситуация
Единое окно заявок (ямы, освещение, аварийные вызовы) распределяет работы между бригадами с разными компетенциями и сменами. Приоритеты меняются; ресурсов меньше, чем заявок.

### Контекст
- Критерии: соблюдение SLA по приоритетам, справедливость между районами, просрочки, стоимость выезда.
- Риск: понижение приоритета аварийной заявки автоматикой недопустимо без подтверждения.

### Постановка МАС
- Агенты бригад + диспетчер; аукцион/квоты/приоритетная очередь.
- Углубление: MARL для политики назначения **или** LLM для маршрутизации текста заявки в категорию с human-in-the-loop.

### Ожидаемый результат для кейса
Эскиз архитектуры, правила эскалации, метрики справедливости и SLA.

## МК-6. Складские роботы-погрузчики

### Исходная ситуация
На складе несколько AGV выполняют задания «взять–везти–поставить». Конфликты на узких проходах; метаэвристика может улучшить маршруты, но нужна координация назначения задач.

### Контекст
- Критерии: makespan, пробег, число ожиданий в узких местах, устойчивость к блокировке клетки.
- Связь с модулем 4: PSO/ACO как оптимизатор маршрутов vs жадный baseline.

### Постановка МАС
- Назначение задач (модуль 2) + метаэвристика маршрутов (модуль 4); при углублении — обучаемая политика объезда (модуль 5).
- Baseline: FIFO + кратчайший путь без учёта загрузки коридоров.

### Ожидаемый результат для кейса
Сопоставление координации и роевой оптимизации; когда достаточно эвристики без MARL.

## Единый шаблон сдачи аналитического кейса

1. Ситуация и целевой результат своими словами.  
2. Матрица альтернатив (не менее трёх) с критериями отклонения.  
3. Выбор минимально достаточной архитектуры и границы применимости.  
4. Эскиз ролей агентов, взаимодействия и точки ответственности человека.  
5. Метрики, план эксперимента (или ссылка на ЛР/экзамен) и условия пересмотра.  
6. При использовании ИИ — промпты и критический разбор.

Формат: 1–3 страницы (СРС) или по требованиям соответствующего КИМ. Шаблон отчёта: [`templates/student-repository/report.md`](../../templates/student-repository/report.md).
