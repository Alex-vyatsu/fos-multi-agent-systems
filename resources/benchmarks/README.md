# Бенчмарки и бейзлайны

Дисциплина требует, чтобы каждое мультиагентное решение сопоставлялось с более простой альтернативой: без базового варианта вывод о пользе МАС не засчитывается ([РПД §6.4](../../docs/rpd.md#64-обязательные-приёмочные-проверки-практического-задания)). Раздел задаёт эталонные среды сравнения и обязательные бейзлайны.

## Обязательные бейзлайны

В любой работе, где оценивается результативность (индикатор **O-2.4**), реализуется хотя бы один базовый вариант из таблицы:

| Бейзлайн | Где применяется | Что показывает |
|---|---|---|
| Случайное или жадное назначение задач | ЛР 2.1, экзаменационное задание | Нижняя граница качества координации |
| Централизованное назначение (единый планировщик) | ЛР 2.1, кейсы, экзаменационное задание | Верхняя граница качества при полной информации и цена централизации по связи и устойчивости |
| Точный или классический алгоритм (например, поиск кратчайшего пути, точное решение малой задачи) | ЛР 4.1 | Эталон качества, относительно которого измеряется выигрыш метаэвристики |
| Одноагентный RL | ЛР 5.1, экзаменационное задание | Проверка, даёт ли мультиагентная постановка выигрыш |
| Независимое обучение (IQL) | ЛР 5.1, рубежный контроль 2 | Базовая точка сравнения для CTDE-схем (VDN, QMIX, MADDPG) |
| Фиксированный сценарий без LLM | ЛР 6.1, экзаменационное задание | Проверка, нужен ли LLM-контур для достижения результата |

## Протокол сравнения

1. **Единая среда и метрики.** Сравниваемые варианты запускаются в одной конфигурации среды; метрики качества, задержки и стоимости определяются до эксперимента.
2. **Повторы.** Не менее **3 запусков** с разными seed на каждую конфигурацию; в отчёте приводятся среднее и разброс, а не единственный лучший запуск.
3. **Фиксация условий.** Версии библиотек, конфигурации, seed, число шагов обучения и оборудование указываются в журнале эксперимента.
4. **Масштаб.** Проверяется не менее двух масштабов (например, разное число агентов) и одно малое локальное изменение правила — для выявления нелинейных эффектов (**FC-3.3**).
5. **Нарушенный режим.** Для сопоставления устойчивости отдельно фиксируются результаты при отказе агента, задержке или потере связи (**ML-6.3**).
6. **Честность сравнения.** Бейзлайну выделяется сопоставимый бюджет (время, число вызовов, вычисления); сравнение обученного агента с ненастроенным базовым вариантом не засчитывается.

## Требования к добавлению

Опишите задачу, метрики, протокол эксперимента, базовые решения, требования к воспроизводимости и правила сравнения. Бенчмарк, требующий вычислительных ресурсов сверх доступных обучающимся, включается только как источник опубликованных результатов для анализа, с явной пометкой об этом.
