# КИМ-1.3. Аналитический кейс «Обоснование применения МАС»

| Параметр | Значение |
|---|---|
| Модуль | 1. Архитектуры агентов и мультиагентных систем |
| Тип КИМ | Аналитический кейс (СРС) |
| Форма контроля | Текущий контроль (СРС); используется как вклад в [рубежный контроль 1](../Midterm-1/README.md) |
| Проверяемые индикаторы | O-2.1 (уровень Б → подготовка к С) |
| Трудоёмкость | В составе СРС 1 (8 а.ч.) |
| Источник | Кейс от индустриального партнёра (или модельный кейс преподавателя) |

## 1. Назначение

Кейс развивает индикатор **O-2.1** в части обоснования: обучающийся анализирует прикладную ситуацию и аргументирует, оправдано ли применение мультиагентной системы по сравнению с одноагентным решением или обычным (централизованным/workflow) процессом. Кейс готовит к рубежному контролю 1, где обоснование выбора архитектуры проверяется на среднем уровне.

## 2. Условия и материалы

- Исходные данные кейса (описание бизнес-/технической ситуации, ограничения, ожидаемый результат) предоставляет индустриальный партнёр либо преподаватель.
- Работа выполняется индивидуально по назначенному варианту в рамках СРС.
- Допускается регламентированное использование ИИ-ассистентов при указании промптов и критическом разборе результата (см. раздел 5).

## 3. Задание

1. Кратко описать ситуацию и целевой результат своими словами.
2. Составить **матрицу альтернатив** решения: фиксированный алгоритм / централизованный процесс / классическая МАС (и, при уместности, MARL / LLM / гибрид) — с плюсами и минусами по масштабу, риску, стоимости и требованиям к ответственности.
3. Обосновать выбор **минимально достаточной** архитектуры; явно указать, при каких условиях мультиагентный подход не оправдан.
4. Предложить эскиз архитектуры выбранного решения (роли агентов, взаимодействие, наблюдаемость) — без реализации.
5. Указать условия, при которых решение следовало бы пересмотреть.

## 4. Что предъявляет обучающийся (формат сдачи)

Аналитическая записка (1–3 страницы) в формате markdown/PDF, содержащая: описание ситуации, матрицу альтернатив, обоснование выбора, эскиз архитектуры и условия пересмотра. Сдаётся коммитом в учебный репозиторий; при рубежном контроле — с краткой устной защитой.

## 5. Правила использования ИИ и внешних ресурсов

- ИИ-ассистенты допускаются для поиска и структурирования, но **итоговое обоснование и выбор — авторские**; использованные промпты указываются.
- Внешние источники приводятся со ссылками; заимствованные формулировки помечаются.
- На защите обучающийся отделяет собственный вывод от сгенерированного текста.

## 6. Критерии оценивания

Оценивание — по [рубрике `rubric-03.md`](rubric-03.md). Ключевое условие положительной оценки: выбор архитектуры обоснован через сопоставление альтернатив, а не декларативно; указаны границы применимости.
