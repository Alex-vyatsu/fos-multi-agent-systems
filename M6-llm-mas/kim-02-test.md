# КИМ-6.2. Тест по темам модуля 6

| Параметр | Значение |
|---|---|
| Модуль | 6. Мультиагентные системы на основе LLM |
| Тип КИМ | Тест (задания с выбором ответа и с открытым кратким ответом) |
| Форма контроля | Текущий контроль |
| Проверяемые индикаторы | LLM-4.1, LLM-4.3 (уровень Б) — знаниевая компонента |
| Охват | Занятия 6.1 «Архитектура мультиагентных LLM-систем», 6.2 «Паттерны взаимодействия и оценка качества», 6.3 «Ответственные и промышленно-эксплуатируемые МАС» |
| Формат | 10–15 заданий; время 20–30 мин |

## 1. Назначение

Тест проверяет знаниевую компоненту индикаторов **LLM-4.1** и **LLM-4.3** на базовом уровне: архитектура мультиагентной LLM-системы (оркестратор, ролевая специализация, A2A, MCP), агентные паттерны (ReAct, Plan-and-Solve, планировщик–исполнитель, критик, дебаты), оценка качества/безопасности/стоимости, ответственный контур и разделение полномочий. Дополняет лабораторную работу [КИМ-6.1](kim-01-practical-work.md).

## 2. Структура и правила проведения

- Задания с выбором одного/нескольких ответов, на соответствие и с кратким открытым ответом.
- Проводится индивидуально письменно/в СДО вуза; при прохождении теста ИИ-ассистенты и внешние источники не допускаются, при дистанционном формате — прокторинг.
- Полный банк заданий с ключами — в [resources/test-banks](../resources/test-banks/README.md).

## 3. Примеры заданий

> Образцы для иллюстрации формата; рабочий вариант формируется из банка.

**1 (выбор одного).** Назначение протокола MCP (Model Context Protocol) в мультиагентной LLM-системе:
а) обучение модели; б) **стандартизованное подключение инструментов и внешнего контекста к модели**; в) сжатие промптов; г) маршрутизация сети.

**2 (выбор одного).** A2A в контексте мультиагентных LLM-систем — это:
а) подключение инструментов; б) **межагентное взаимодействие (agent-to-agent)**; в) дообучение модели; г) кэширование ответов.

**3 (соответствие).** Сопоставьте паттерн и уровень: ReAct / Plan-and-Solve / «критик» / дебаты ↔ «внутри агента» / «внутри агента» / «между агентами» / «между агентами».

**4 (выбор одного).** Согласно принципу ответственного контура, вывод LLM:
а) является окончательным решением; б) **считается проверяемым предложением до подтверждения человеком или ответственной ролью**; в) не журналируется; г) заменяет валидацию.

**5 (краткий ответ).** Назовите не менее двух механизмов отказоустойчивости мультиагентной LLM-системы. *(Ответ: тайм-ауты, повторные попытки, резервный сценарий, human-in-the-loop.)*

**6 (выбор одного).** Agent Card объявляет capability агента. Что ещё нужно
до делегирования значимого действия? а) считать capability разрешением;
б) **проверить происхождение/версию и отдельное полномочие на действие**;
в) передать агенту исходный пользовательский token; г) отключить журнал.

**7 (соответствие).** Сопоставьте сущность и границу:
`task/message/artifact/cancel` ↔ **A2A**; `tool/resource/scope/error` ↔
**MCP**.

**8 (краткий ответ).** Почему повтор запроса после потерянного ответа не должен
повторять внешний эффект? *(Ответ: повтор доставки возможен; нужен стабильный
task/effect key и идемпотентная проверка ledger.)*

## 4. Шкала оценивания

| Доля верных ответов | Баллы (в компоненте «тест») |
|---|:--:|
| < 55% | 0 (не зачтено) |
| 55–69% | 1 |
| 70–84% | 1.5 |
| ≥ 85% | 2 |

Тесты по всем модулям суммарно — до **10 баллов** компонента «текущий контроль» (см. [раздел 4 корневого README](../README.md#4-итоговая-оценка)).
